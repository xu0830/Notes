# CLR

## GC

值类型保存在 stack 上，由系统自动管理，随着函数的执行作用域执行完毕而自动出栈，所以这一类型的资源不是 GC 所关心的对象，

GC 主要是针对保存在 heap 的资源

### 分配对象

#### 大对象分配

超过 85000 个字节

从大对象堆段分配

不会对大对象进行搬迁压缩

#### 小对象分配

从短暂堆或者自由对象列表分配

#### 区域

CLR初始化时在内存里开辟一段空间

一个区域分为多个堆（普通堆和短暂堆）   

### 垃圾回收

上一次垃圾回收后创建的对象为第0代对象，垃圾回收后还存在的0代对象演变为1代，1代演变为2代

1代对象每执行10次垃圾回收循环，检查一遍

2代对象每执行100次垃圾回收循环，检查一遍

### 析构函数

托管堆中内存的释放和析构函数的执行属于两个不同的线程

有析构函数的目标对象会被放进一个“终结队列”，然后系统调用另一个高优先级线程来执行 Finalize（）方法



带有析构函数的对象和其引用对象的生命周期会变长，进行两次垃圾回收处理才能释放



#### 过程 

​	标记，计划，重定位，压缩，清扫

#### 触发GC的条件

分配对象找不到可用空间 （A a = new A()）

分配量超过CLR初始化设置的阈值

收到物理内存不足的通知

直接调用 GC.Collect（）

#### 步骤

1.停止其他线程（切换其他线程到抢占模式）

​	合作模式：在CLR里面运行的线程，可以无限制的访问托管堆和非托管模式

​	抢占模式：只能访问非托管堆，托管堆不可以访问（ GC垃圾回收的时候，会改变内存空间，回收无用对象，防止线程访问到这些对象）

2.重新判定传入的GC回收目标代是否合适

目标代(generation) : 0, 1, 2 (小对象的2代)， 2（大对象的2代） 

​	判断条件

​		碎片空间率

​		短暂堆剩余空间

​		卡片扫描效率（卡片  card_table，标记隔代引用的对象)

​		物理内存占用率

3.判断是否执行后台GC

​	执行后台GC，标记和清扫

​	不执行后台GC，普通GC，标记，计划，重定位，压缩，清扫

### card_table 表

C++级的性能优化

数组中的每个元素指向 （128 / 256）个字节的对象存储地址

### brick 表

优化 CLR 模拟压缩的时间

在标记完成后，进行计划的过程中创造的表

.NET CLR中分为固定对象和非固定对象

固定对象，非托管代码保存托管代码的指针的时候，在非托管代码中保存的不可移动指针的对象

其余为非固定对象 

固定对象：DLLIMPORT("" )

标记阶段后，存活的对象会被标记为1，没存活的对象标记为0

存活的对象和固定对象构成了托管堆对象值的三类

​	标记存活为0

​	存活 标记为1，固定对象标记为0

​	存活和固定标记都为1

CLR在GC回收的计划阶段，会归类相邻并同属一类的对象

相邻两个对象为固定对象或一个固定一个非固定，归纳为固定plug

相邻两个都为非固定对象，归纳为非固定plug，

为了枚举plug，多个plug会组成plug树

当plug树增多的时候，线性扫描托管堆时间就会变得很长

Brick表为了优化时间问题，分割了plug树，Brick是一个bit数据

数组元素为plug树根节点离平台字节（32位2048，64位4096）的距离

## 托管堆

程序运行时，进程存放引用类型变量的内存，全局唯一

根据CPU核心树分为多个区域，几核心几区域

每个区域分为四个代，0，1, 2（小对象），2（大对象）

每个代中包含了静态数据（static_data)和动态数据（dynamic_data)

静态数据包含了分配量阈值的上下限限制，动态数据包含了分配量阈 值

## 栈

先进后出，线程栈，每个线程存放变量和值类型的内存，跟随线程的生命周期

## .NET 6 史上最快的原因

关键的地方使用汇编代码，（二进制比汇编快，但无法在程序中使用）

CLR所有的函数调用都经过 precodefixupthunk() 采用汇编语言

##  IDisposable

实现了 IDisposable 接口的对象在回收时要经过两次 GC 才能真正的释放掉，因为 GC 要先安排 CLR 调用终结器

```
public void Dispose()
{
	Dispose(true);
	GC.SuppressFinalize(this);
}
```

除了静态变量，局部变量置为 null 的语句，会被 JIT 优化忽略掉
