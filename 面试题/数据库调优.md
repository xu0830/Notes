## Sql 调优

- 尽量减少数据库的访问次数

- 尽量把使用的索引放在选择的首列

- 避免使用通配符 *

- 不要使用游标

- 避免使用不兼容的数据类型

  float 和 int， char 和 varchar， binary 和 varbinary 是不兼容的

  数据类型的不兼容可能使优化器无法执行一些本来可以进行的优化操作

- 尽量避免在 where 子句中对字段进行函数或表达式操作

  这将导致引擎放弃使用索引而进行全表扫描

- 避免使用 !=、<>、IS NULL、IS NOT NULL、IN、NOT IN 等操作符

  IN 会走索引，但当 IN 的取值范围较大时会导致索引失效，走全表扫描

  这会使系统无法使用索引，而只能直接搜索表中的数据，

  优化器将无法通过索引来确定将要命中的行数，因此需要搜索该表的所有航

- 尽量使用数字型字段

- or 连接同一个字段时索引不会失效，连接不同字段时索引失效

- 避免模糊查询时索引失效, Like ‘%%’，LIKE 'L%'(走索引)

- IS NULL 不走索引，IS NOT NULL 走索引

- 没有必要要求为 NULL，最好设置空字符串默认值

- 能用 BETWEEN 就不要用 IN

  IN 会走索引，但当 IN 的取值范围较大时会导致索引失效，走全表扫描

- 能用 DISTINCT 就不要用GROUP BY

- 能用 UNION ALL 就不要用 UNION

- 尽量不要用 SELECT INTO ，会导致表锁定，阻止其他用户访问

- 检查记录是否存在使用 EXISTS() ，而不是 COUNT(), Exists 一旦看到需要的结果就退出

- 合理使用临时表，将数据量大的表传输到临时表，使用临时表进行表关联

  （SELECT  * INTO #Temp FROM  t）
  
  SELECT INTO 会锁定 tempdb 数据库，不允许其他用户创建临时表，在7.0及以上版本修复

- 子查询与 CTE 查询性能理论上是相同的

## COUNT 执行效率

- count(1)，用 1 代替代码行，统计包含 null 的数据
- count(字段)，不统计 null 数据，列为主键时 ，比 count(1) 快，否则 count(1) 快
- count( * )， 统计 null 数据，表中只有一个字段，count( * ) 最优
